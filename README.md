# Health AI — фронтенд

Сайт Health AI: лендинг, правовые страницы, страница поддержки и веб-версия
приложения. Next.js 15 (App Router), TypeScript, CSS Modules на токенах
дизайн-системы Classical, светлая и тёмная темы, русский и английский.

Работает против того же API, что и приложение на iPhone: контракт — §1–16
в `health-ai-backend/docs/BACKEND_API.md`.

Дизайн-источник: проект «Дизайн приложения для отслеживания питания»,
компонент `Health AI - Landing.dc.html`. iOS-приложение и контракт бэкенда:
репозиторий `health-ios-ai-app`.

## Быстрый старт

```bash
npm ci
cp .env.example .env.local   # укажите API_BASE_URL
npm run dev                  # http://localhost:3000 -> /ru
```

Сайту нужен работающий API. Локально он поднимается своим репозиторием:

```bash
cd ../health-ai-backend && make up   # API на :8080, письма на :8025
```

Без API откроются лендинг и формы; экраны дневника покажут ошибку, а правовые
страницы — заглушку «документ временно недоступен».

```bash
npm run typecheck     # tsc --noEmit
npm run lint
npm run test:unit     # Vitest: парсер Markdown, валидация формы
npm run test:e2e      # Playwright: лендинг, тема, форма, правовая страница
```

## Docker

```bash
docker compose up --build     # standalone-сборка, порт 3000
```

`next.config.ts` собирает `output: 'standalone'`, образ многоступенчатый и
запускается непривилегированным пользователем.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `API_BASE_URL` | Базовый адрес API, тот же, что `APIBaseURL` в iOS |
| `LEGAL_REVALIDATE_SECONDS` | Период ISR для правовых документов (по умолчанию 3600) |
| `NEXT_PUBLIC_SITE_URL` | Публичный адрес сайта, нужен метаданным |
| `NEXT_PUBLIC_SUPPORT_EMAIL` | Почта поддержки в подвале и в форме |
| `NEXT_PUBLIC_APP_VERSION` | Версия сайта, уходит в `X-App-Version` и видна в списке устройств |
| `SITE_DEVICE_ID` | Идентификатор «устройства» сайта для запросов без человека |

Переменные с префиксом `NEXT_PUBLIC_` Next подставляет в код **на сборке**, а
не читает при старте: в образе они задаются аргументами сборки, а не
переменными контейнера.

Полный список с комментариями — в `.env.example`.

## Иконки

В `public/` лежит тот же знак, что у приложения в App Store: `favicon-16/32/48`,

## Веб-версия приложения

Приложение живёт по адресу `/{locale}/app` и повторяет экраны iOS-версии:
дневник дня, запись еды фразой и из каталога, каталог продуктов с правкой,
разборы, итоги за неделю и месяц, настройки. Вход, регистрация в три шага и
восстановление доступа — `/{locale}/login`, `/register`, `/recover`.

Что добавлено специально для браузера: сокращения N/T/P/R/I/S и `?`,
сортируемая таблица дневника, календарь месяца сеткой и сравнение двух дней.
Активность, шаги и вес показываются только для чтения с пометкой «из Здоровья»:
в браузере этого источника нет.

Данные настоящие: дневник, каталог, отчёты и профиль приходят из API. Разбор
фразы делает бэкенд (`POST /ai/food/resolve`) — промпты и ключи вендоров живут
там же, а не в браузере.

Выбранный день живёт в адресе (`?date=2026-09-06`), а не в состоянии страницы:
так его можно переслать ссылкой, вернуться к нему кнопкой «назад» и — главное —
собрать страницу на сервере уже с данными этого дня.

Шторка меню на узких экранах держится на `:checked` и работает до гидратации.

### Как устроен доступ к API

Браузер разговаривает только со своим сервером, а с API разговаривает сервер.
Токены лежат в httpOnly-cookie и в браузер не попадают вовсе: токен, доступный
скриптам страницы, уезжает вместе с первой же XSS.

- `src/lib/api/client.ts` — единственное место, где сайт ходит в API. Собирает
  заголовки §1, разбирает конверт ошибок §2.
- `src/middleware.ts` — заводит идентификатор браузера, обновляет access-токен
  до рендера и не пускает в `/app` без сессии.
- `src/lib/api/refresh.ts` — обмен refresh-токена. Ротация обязательна, и
  повторное предъявление использованного токена отзывает всю цепочку сессий,
  поэтому одновременные попытки склеиваются в одну.
- `src/app/api/**` — route handlers: всё, что пишет данные, идёт через них.

## Локализация

Локаль — первый сегмент пути. Middleware редиректит корень по
`Accept-Language` и кладёт локаль в заголовок `x-locale`, откуда её читает
корневой layout (для `lang` и словаря). Тексты — типизированные словари
`src/i18n/dictionaries`: английский обязан совпадать с русским по форме
(`satisfies Dictionary`), иначе сборка падает.

## Темы

Токены Classical живут в `src/styles/classical.css` без изменений. Тёмная тема —
только переопределение переменных на `html[data-theme="dark"]`; компоненты о
теме не знают. Выбор пользователя (`light` · `dark` · `system`) хранится в
`localStorage` под ключом `healthai-theme` и ставится инлайн-скриптом до первой
отрисовки, чтобы не мигал светлый кадр.
