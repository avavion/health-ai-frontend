# Форма поддержки: что нужно от бэкенда

Форма обязательна для App Store: Apple требует рабочий канал связи на странице
поддержки приложения. Сейчас фронтенд собран, валидирует ввод и умеет отправлять
обращение, но транспорт не выбран — по умолчанию `SUPPORT_TRANSPORT=stub`, и
route handler отвечает 501, а форма показывает пользователю адрес почты.

Чтобы включить отправку, бэкенду нужен один роут. Ниже контракт, на который
фронтенд уже рассчитан: достаточно реализовать его и выставить
`SUPPORT_TRANSPORT=backend`.

## Роут

```
POST {API_BASE_URL}/support/requests
Content-Type: application/json
```

Авторизация не требуется: обращение может прислать человек без аккаунта
(например, потерявший доступ). Путь настраивается переменной
`SUPPORT_BACKEND_PATH`, если у вас принято другое имя.

### Тело запроса

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `email` | string | да | Почта для ответа, проверена на фронте регуляркой |
| `topic` | enum | да | `app-question` · `bug` · `account-recovery` · `account-deletion` · `data-question` · `other` |
| `message` | string | да | Не короче 10 символов |
| `consent` | boolean | да | Всегда `true`: без согласия форма не отправляется |
| `locale` | string | да | `ru` или `en` — на этом языке ждут ответ |
| `name` | string | нет | Имя, если указано |
| `userAgent` | string | нет | Заполняет клиент, помогает разбирать баги |
| `appVersion` | string | нет | Если обращение пришло из приложения |

```json
{
  "email": "anna@example.ru",
  "topic": "bug",
  "message": "Приложение падает при сохранении обеда.",
  "consent": true,
  "locale": "ru",
  "name": "Анна",
  "userAgent": "Mozilla/5.0 (iPhone; CPU iPhone OS 18_5 …)"
}
```

### Ответы

| Код | Тело | Когда |
| --- | --- | --- |
| 202 | `{ "ticket": "HA-482913" }` | Обращение принято и поставлено в очередь на отправку |
| 422 | `{ "error": "validation-failed", "fields": { "email": "invalid-email" } }` | Не прошло серверную валидацию |
| 429 | `{ "error": "rate-limited", "retry_after": 60 }` | Слишком часто с одного адреса или IP |
| 5xx | `{ "error": "..." }` | Фронтенд покажет «напишите письмом» |

`ticket` показывается пользователю как номер обращения. Формат свободный,
фронтенд его только отображает; удобно `HA-` плюс шесть цифр.

## Что бэкенд делает с обращением

1. Валидирует поля повторно — на клиентскую проверку полагаться нельзя.
2. Ограничивает частоту: не больше 5 обращений с одного email и 20 с одного IP в час.
3. Проверяет на спам (honeypot-поля во фронте нет, антиспам на стороне сервера).
4. Кладёт обращение в таблицу `support_requests` и отправляет письмо на
   `support@healthai.app` с `Reply-To` из `email`.
5. Отправляет пользователю подтверждение с номером обращения.
6. Хранит обращение не дольше срока из политики (12 дней после закрытия) —
   в политике конфиденциальности это уже заявлено.

## Альтернатива без бэкенда

Если роут не появится, можно оставить отправку на Next: `SUPPORT_TRANSPORT=smtp`,
`SUPPORT_SMTP_URL` и `SUPPORT_MAIL_TO` в окружении, а в
`src/app/api/support/route.ts` добавить ветку с Nodemailer или Resend. Тогда
письмо уходит напрямую, но нет ни истории обращений, ни антиспама на сервере.

## Открытые вопросы к бэкенду

- Имя роута: `support/requests` или иное?
- Кто владеет ящиком `support@healthai.app` и настроены ли SPF/DKIM для домена?
- Нужен ли номер обращения в одном формате с iOS-приложением?
